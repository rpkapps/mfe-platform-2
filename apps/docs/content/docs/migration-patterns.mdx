---
title: Migration patterns
description: Moving an existing application onto the platform, from a single SPA, from iframes, or from an older micro-frontend setup.
---

## From a single-page application

**Goal**: split a large TanStack Router (or React Router) app into a shell and several MFEs without a rewrite.

1. Create the shell with `@platform/host` around the existing chrome (navigation, header, auth). Keep the existing router as the shell router and add `createTanStackShellNavigation(router)`.
2. Pick one feature area with its own URL prefix. `pnpm dlx @platform/cli create <area>` next to the monolith, move its route files under `src/routes` (they are TanStack routes already or become ones: `createFileRoute("/list")` instead of `<Route path="list">`).
3. Replace global state access with `usePlatform()` and route context; replace direct storage with `createPlatformStorage`; replace the app's own command and settings registries with the platform hooks.
4. Mount it: `<MfeOutlet mfeId="<area>" />` on the shell route `/<area>/$`, and remove the monolith's routes for that prefix.
5. Repeat per area. Shared UI stays in `@tecton/react` (or a shared package published to your registry) — never in a cross-MFE import.

What changes for developers: routes keep their code; links across areas use `useNavigation().navigate("/other-area/...")` instead of relative routes.

## From iframes

**Goal**: replace iframe embedding with in-process remotes while keeping isolation.

- Each iframe application becomes an MFE with its own React root, scoped CSS and overlay root, which covers the isolation iframes gave you for **trusted** code. Untrusted third-party content must stay in an iframe; see [Unsupported cases](/docs/unsupported-cases).
- `postMessage` protocols become platform contracts: context through `usePlatform`, navigation through the shell history, notifications through `useNotifications`, commands through registrations.
- Deep links keep working: iframe query parameters become route params or search params under the route prefix. `routePrefix` can preserve the old public URL.
- Per-iframe configuration becomes per-MFE runtime environment values.

## From an older micro-frontend setup

**Single-SPA or a custom orchestrator**

- Lifecycle functions (`bootstrap`/`mount`/`unmount`) map onto `createMfe` (`mount`/`dispose` are generated). Delete the custom history synchronisation: the shell history adapter replaces it.
- Replace `registerApplication` with the registry / runtime configuration; activity functions become route prefixes.
- Module Federation `remotes`/`exposes` configuration in each app is replaced by `platform()` inference.
- If the old setup shared React through a global (`window.React`), remove it: sharing is negotiated per version group.

**Hand-written Module Federation**

- Move `shared` decisions into `mfe.config.ts` overrides only where they differ from inference; delete `federation.config.js`.
- The exposed module becomes `src/mfe.tsx` with `createMfe`; the host stops calling `loadRemote` directly.
- Version negotiation moves from `requiredVersion` guesswork to manifest requests and host negotiation; check the devtools _Dependencies_ panel after migrating.

## Incremental checklist

- [ ] `mfeId` chosen and persisted (`.platform/identity.json`); storage keys migrated with `migrate` where formats changed.
- [ ] Route prefix decided; old URLs redirected by the shell where the prefix changed.
- [ ] Guards moved to `beforeLoad`; permission groups mapped.
- [ ] Commands, settings, help and release notes registered through the hooks.
- [ ] Runtime values moved from `VITE_*` to `env` declarations.
- [ ] `platform lint` passes; the harness runs the MFE alone.
- [ ] E2E flows run against the harness.
