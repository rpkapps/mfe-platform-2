## Setup

`platform create` generates the configuration and the script; nothing is copied by hand:

```ts title="eslint.config.ts"
import { platformConfig } from "@platform/cli/eslint"

export default platformConfig()
```

```json title="package.json"
{ "scripts": { "lint": "platform lint", "lint:fix": "platform lint --fix" } }
```

`platform lint` runs the same configuration CI uses. The config composes, in order: the generated-file ignores, `@eslint/js` recommended, `typescript-eslint` recommended (type-checked with `typed: true`), browser + node globals, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y` (`.jsx`/`.tsx`), `@tanstack/eslint-plugin-router`, the `@platform` plugin at its recommended severities, a few TypeScript conventions (`no-unused-vars` with `_` prefixes, inline `type` imports, `prefer-const`) and relaxations for tests (`no-non-null-assertion`, `no-raw-browser-storage` and `no-unsafe-runtime-env-access` off in `*.test.*`, `__tests__/**`, `e2e/**`).

```ts
platformConfig({
  typed: true, // recommendedTypeChecked + projectService; config files and scripts stay untyped
  react: true, // eslint-plugin-react-hooks (default true)
  tanstackRouter: true, // default true
  a11y: true, // default true
  rules: { "@platform/require-telemetry-context": "off" }, // severity overrides, applied last
  ignores: ["src/legacy/**"], // in addition to the generated files
  tsconfigRootDir: import.meta.dirname, // for typed linting (default: process.cwd())
  extends: [{ files: ["src/experimental/**"], rules: { "@platform/no-unsafe-runtime-env-access": "warn" } }],
})
```

Ignored by default: `**/routeTree.gen.ts`, `**/*.gen.ts`, `**/*.gen.tsx`, `**/.platform/**`, `**/dist/**`, `**/node_modules/**`, `**/platform-manifest.json`, `**/coverage/**`, `**/playwright-report/**`, `**/test-results/**`.

Every diagnostic links to the rule's section on this page (`/docs/linting#<rule-name>`). Rules are named `@platform/<rule>`.

## Rules

`error` by default unless noted.

### no-raw-browser-storage

Reports `localStorage`, `sessionStorage` (also through `window.` / `globalThis.`) and `document.cookie` writes in MFE code. Raw storage bypasses namespacing, schema validation, cross-tab synchronisation and diagnostics. Use [`createPlatformStorage`](/docs/storage). Option `allow`: file globs where raw access is allowed (tests, adapters).

### no-direct-module-federation

Reports imports of `@module-federation/*`, calls to federation runtime APIs (`registerRemotes`, `loadRemote`, `init`…) and reads of federation globals. Federation is generated by `@platform/vite` and driven by `@platform/host`; expose widgets with `createWidget` and navigate with `useNavigation()` instead. See [Module Federation](/docs/module-federation).

### no-generated-file-edits

Reports hand-written content in generated files (`routeTree.gen.ts`, `*.gen.ts`, `.platform/*`, `platform-manifest.json`: they must keep their generator banner and stay in the lint ignores) and imports that reach into `.platform/` internals. Option `patterns`: additional generated-file globs.

### registration-cleanup

Default `warn`. Reports `useRegisterCommand`, `useRegisterSettingsGroup`, `useRegisterSettingsField`, `useRegisterHelp` and `useRegisterReleaseNotes` called outside a React component or a custom `use*` hook (module scope, plain functions, callbacks): such registrations are never cleaned up. Register from a component (or render the matching `<…Registration definition={…} />`).

### stable-mfe-id

Reports a non-literal `mfeId` in `createMfe({ mfeId })` or `mfe.config.ts`, an id that is not kebab-case, or one that differs from `.platform/identity.json`. The identity namespaces storage, settings and commands; renaming is a deliberate migration ([Manifests](/docs/manifests#identity-persistence)).

### valid-settings-definition

Reports settings groups and fields passed to `useRegisterSettingsGroup`, `SettingsRegistration` and `useRegisterSettingsField` that are malformed: non-kebab-case keys, `fields` not an object literal, a field without `defaultValue` or with `value`, `managedBy: "mfe"` without `route`, options that are not `{ value, label, … }`, a plain object as `schema`, duplicate field keys, `useRegisterSettingsField` without `key` and `group`. See [Settings](/docs/settings).

### valid-command-definition

Reports commands passed to `useRegisterCommand` and `CommandRegistration` with a non-local or non-kebab-case `id`, an empty `label`, a malformed shortcut (modifiers `mod`, `ctrl`, `alt`, `shift`, `meta` joined by `+` and exactly one key; no repeated modifier), neither `handler` nor `route`, or non-literal `keywords`. See [Commands](/docs/commands).

### valid-capability-usage

Reports SDK APIs whose capability `mfe.config.ts` removes (`capabilities.remove`) — the host would not grant it and the call would fail with `CAPABILITY_UNAVAILABLE` — and `useCapability()` with an unknown id. See [Platform context](/docs/platform-context#capabilities).

### valid-manifest-config

Validates `defineMfeConfig({...})` statically: unknown keys, `routePrefix` and `mfeId` format, `discoverable` not a boolean, `env` keys that look sensitive or values that are not declaration objects, `shared` values that are not `boolean | { version?, bundle?, singleton?, scope? }` or use an invalid scope, unknown capability ids, `navigation.title` not a string. See [Vite configuration](/docs/getting-started/vite-configuration).

### no-cross-root-component-passing

Reports React elements, components, hooks or contexts where the platform expects plain data: notifications, telemetry attributes, storage defaults, command metadata and widget props. Every MFE and widget renders in its own React root; only data crosses ([React roots](/docs/isolation/react-roots)). Help `content` and settings `renderer` components are converted by the SDK and are fine.

### require-telemetry-context

Default `warn`. Reports `telemetry.track()` with a non-literal or badly formed event name (`^[a-z][a-z0-9]*([.:-][a-z0-9]+)*$`), `telemetry.error(error)` in a catch block without attributes such as `{ boundary }`, and MFE code that constructs its own telemetry (`createTelemetry`) instead of `useTelemetry()` / `context.platform.telemetry`. See [Telemetry](/docs/telemetry).

### valid-route-prefix

Reports invalid `routePrefix` literals (leading `/`, lowercase segments, no trailing slash) and route files whose `createFileRoute` path hard-codes the MFE prefix (`/asset-tracker/assets` instead of `/assets`). See [Route prefixes](/docs/route-prefixes).

### valid-mfe-identity

Reports more than one `createMfe()` call per module, a `src/mfe.tsx` that does not default-export the `createMfe(...)` call (directly or through a binding), and widget keys in `createMfe({ widgets })` that are not kebab-case.

### no-unsupported-dependency-sharing

Reports `shared` entries in `mfe.config.ts` that name packages which are not dependencies, `singleton: true` on React packages (React is shared by version group, never as a singleton), and share scopes other than `default` or `react<major>`. See [Dependency sharing](/docs/dependency-sharing).

### no-unsafe-runtime-env-access

Reports `window.__PLATFORM_CONFIG__`, fetches of `/platform-config.json`, `import.meta.env.*` and `process.env.*` reads in MFE source. Runtime values are declared in `mfe.config.ts` (`env`) and read with `useRuntimeEnv()` / `context.platform.runtime`. Build and config files are exempt by default; option `allow` adds file globs. See [Runtime environment](/docs/runtime-environment).

### no-direct-mfe-import

Reports imports of other MFEs: packages named `@scope/mfe-*`, federation aliases, and sources that resolve outside the project. MFEs compose through widgets, commands and navigation; shared code ships as a published package. Option `allow`: import specifiers (globs) that are allowed.

## Custom configs

`platformConfig` covers the scaffold. For a custom flat config, add the plugin directly:

```ts
import plugin from "@platform/cli/eslint"

export default [
  plugin.configs.recommended, // { plugins: { "@platform": plugin }, rules: RECOMMENDED_RULES }
  { rules: { "@platform/registration-cleanup": "error" } },
]
```

## Tests

Every rule has unit tests (`@typescript-eslint/rule-tester`) and `platform validate` checks that the project's lint configuration is the platform one. A freshly scaffolded project passes `platform lint` without manual configuration.
