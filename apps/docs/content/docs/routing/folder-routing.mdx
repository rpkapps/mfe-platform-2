## File routes

Routes live under `src/routes` and follow TanStack Router's file conventions without any addition:

```text
src/routes/
├── __root.tsx            → the MFE root (layout + context type)
├── index.tsx             → /<prefix>
├── settings.tsx          → /<prefix>/settings
├── assets/
│   ├── index.tsx         → /<prefix>/wells
│   └── $wellId.tsx      → /<prefix>/wells/:wellId
└── reports.$reportId.tsx → /<prefix>/reports/:reportId (flat syntax)
```

Paths inside the MFE are written relative to the MFE root (`/wells/$wellId`). The shell mounts the whole tree under the MFE's [route prefix](/docs/route-prefixes); `Link` and `navigate` inside the MFE keep using the relative form, and the shell-backed history translates them.

```tsx title="src/routes/wells/index.tsx"
import { createFileRoute, Link } from "@tanstack/react-router"

export const Route = createFileRoute("/wells/")({
  staticData: { breadcrumb: "Wells", navigation: { title: "Wells", order: 1 } },
  component: () => (
    <ul>
      <li>
        <Link to="/wells/$wellId" params={{ wellId: "w01" }}>
          16/2-D-12 H
        </Link>
      </li>
    </ul>
  ),
})
```

## The generated route tree

`@platform/vite` configures `@tanstack/router-plugin` with:

```ts
{
  target: "react",
  autoCodeSplitting: true,
  routesDirectory: "src/routes",
  generatedRouteTree: "src/routeTree.gen.ts",
}
```

`src/routeTree.gen.ts` is regenerated on every change and is the single input of `createMfe({ routeTree })`. It is committed for readability and never edited.

## Typed routes

Route ids, params, search and loader data flow from the generated tree once the MFE router is registered with TanStack. `createMfe` builds a `MfeRouter<typeof routeTree>`; the scaffold registers it in `src/platform.d.ts`:

```ts title="src/platform.d.ts"
import type { MfeRouter } from "@platform/mfe-react"
import type { routeTree } from "./routeTree.gen"

declare module "@tanstack/react-router" {
  interface Register {
    router: MfeRouter<typeof routeTree>
  }
}
```

With it, `Route.useLoaderData()`, `Route.useSearch()`, `useParams`, `getRouteApi`, `<Link to="/wells/$wellId" params={{ wellId }}>` and `redirect({ to })` are checked against the tree; a `to` that does not exist is a type error. The conformance MFEs put the same augmentation at the bottom of `src/mfe.tsx`.

## Code splitting

`autoCodeSplitting: true` splits each route's `component`, `pendingComponent`, `errorComponent`, `notFoundComponent` and loader-adjacent code into its own chunk. The Module Federation build keeps those chunks next to the remote entry, so a shell that mounts `/well-planner/wells/w01` downloads the remote entry, the shared-dependency negotiation result and the chunks of the matched routes only.

Preloading works as in a stand-alone app: the router is created with `defaultPreload: "intent"`, and `Link preload="viewport"` is honoured.

## Route metadata in the manifest

The plugin statically reads each route file and writes route metadata into the manifest (`routes[]`): `path`, `fullPath`, `file`, `guarded` (whether `beforeLoad` is declared), and the `staticData` fields `breadcrumb`, `navigation` and `permissionGroups`. The shell uses it for the command palette (`navigation.title` and `keywords` are searchable before the remote loads) and permission preflight.

```ts
staticData: {
  breadcrumb: "Wells" | { label, dynamic?, hidden?, fromLoader?: "title" },
  navigation: { title, description?, icon?, keywords?, order?, hidden? },
  permissionGroups: ["wells:read"],
}
```

The `StaticDataRouteOption` interface is augmented by `@platform/mfe-react`, so these keys are typed.

## What the platform adds

Nothing in the route files is platform-specific. The integration is supplied around them:

- `createMfeRouter({ routeTree, bridge })` (called by `createMfe`) creates the router with a [shell-backed history](/docs/routing/shell-history), the route prefix as `basepath` and `context: { platform }`.
- The root route type `MfeRouterContext` gives every `beforeLoad` and loader a typed `context.platform`; see [Route guards](/docs/routing/route-guards).
- Route matches publish [breadcrumbs](/docs/routing/breadcrumbs) to the shell.

## Advanced: creating the router yourself

`createMfe` covers every normal case. When you need extra TanStack router options, pass them through `createMfe({ router })`; `createMfeRouter` is public for tests and unusual hosts:

```ts
import { createMfeRouter } from "@platform/mfe-react"

const router = createMfeRouter({
  routeTree,
  bridge,
  displayName: "Wells",
  defaultPreloadStaleTime: 30_000,
})
// later: disposeMfeRouter(router)
```
