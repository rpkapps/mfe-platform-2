<Callout title="One guard system">
  `beforeLoad`, `redirect`, `notFound`, loader errors, pending and error components are TanStack
  Router's own. The platform injects `context.platform` and makes sure a guard failure stays
  inside the MFE.
</Callout>

## `context.platform`

Every route receives the platform context through TanStack's router context. Declare it once on the root route:

```tsx title="src/routes/__root.tsx"
import { createRootRouteWithContext, Outlet } from "@tanstack/react-router"
import type { MfeRouterContext } from "@platform/mfe-react"

export const Route = createRootRouteWithContext<MfeRouterContext>()({
  component: () => <Outlet />,
})
```

`context.platform` exposes:

| Field                                          | Type                                         |
| ---------------------------------------------- | -------------------------------------------- |
| `user`                                         | `PlatformUser \| null`                       |
| `permissionGroups`                             | `string[]`                                   |
| `permissions`                                  | `{ hasGroup, hasAnyGroup, hasAllGroups }`    |
| `tenant`, `project`, `job`                     | context objects or `null`                    |
| `locale`, `timezone`, `theme`, `resolvedTheme` | strings                                      |
| `featureFlags`                                 | typed through `Register.featureFlags`        |
| `capabilities`                                 | approved `CapabilityId[]`                    |
| `runtime`                                      | `{ environment, env, shared }` (typed `env`) |
| `telemetry`                                    | enriched `Telemetry`                         |
| `navigation`                                   | `PlatformNavigation`                         |
| `mfeId`, `instanceId`                          | identity                                     |
| `revision`                                     | increments on every context change           |
| `getState()`, `subscribe()`                    | escape hatches                               |

## Permission checks

```tsx title="src/routes/wells/$wellId.tsx"
import { createFileRoute, redirect } from "@tanstack/react-router"

export const Route = createFileRoute("/wells/$wellId")({
  staticData: { breadcrumb: { fromLoader: "breadcrumb" }, permissionGroups: ["wells:read"] },
  beforeLoad: ({ context, params }) => {
    if (!context.platform.permissions.hasGroup("wells:read")) {
      throw redirect({ to: "/", search: { denied: params.wellId } })
    }
    if (params.wellId === "restricted" && !context.platform.permissions.hasGroup("admin")) {
      throw new Error(
        "Only admins may open the restricted well (guard error stays inside the MFE)."
      )
    }
  },
})
```

This is the `well-planner` fixture. The E2E suite switches the shell user to one without `wells:read` while `/well-planner/wells/w01` is open and sees the redirect to `/well-planner?denied=w01` — no remount, the shell untouched — and, for a viewer opening `restricted`, the guard error rendered by the route's `errorComponent`.

`staticData.permissionGroups` is optional and only feeds the manifest: the shell can [preflight](/docs/permission-groups#preflight) the remote before loading it, and the palette hides routes the user cannot open. The `beforeLoad` check is the one that decides.

## Redirects across MFEs

`redirect({ to })` targets a path inside the MFE. To leave the MFE, use the platform navigation, which takes an absolute shell href:

```ts
beforeLoad: ({ context }) => {
  if (!context.platform.tenant) {
    context.platform.navigation.navigate("/select-tenant")
    throw new Error("tenant required")
  }
}
```

## Loaders and errors

Loaders run on the client after the MFE mounts (only the shell is server-rendered). A thrown error lands in the nearest `errorComponent`:

```tsx
export const Route = createFileRoute("/wells/$wellId")({
  loader: async ({ params, context }) => {
    const well = await fetchWell(params.wellId)
    if (!well) throw notFound()
    return well
  },
  pendingComponent: () => <Skeleton className="h-32" />,
  errorComponent: ({ error, reset }) => <AssetError error={error} onRetry={reset} />,
  notFoundComponent: () => <p>No such well.</p>,
  component: AssetPage,
})
```

Routes without their own components fall back to the ones passed to `createMfe({ errorComponent, pendingComponent, notFoundComponent })`, and finally to the platform defaults (`DefaultRouteErrorComponent`, which retries with `router.invalidate()`, `DefaultPendingComponent`, `DefaultNotFoundComponent`): plain, Tecton-free markup with the `PlatformError` hint and docs link when available. Render errors that escape the router reach the `MfeErrorBoundary` at the MFE root, which reports them to telemetry and diagnostics and offers _Retry_.

## Reacting to context changes

Context changes (a new project, a changed permission group) bump `context.platform.revision`. `createMfeRouter` subscribes to the context store and calls `router.invalidate()`, so:

- loaders that read the context re-run,
- `beforeLoad` guards run again and can redirect,
- the MFE root is preserved — nothing remounts.

Use `revision` in a loader's dependencies when you cache by hand:

```ts
loader: ({ context }) => queryClient.ensureQueryData(wellsQuery(context.platform.project?.id))
```

## Where failures land

| Failure                                                          | Handled by                                                                          |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Manifest missing, invalid, protocol mismatch, remote unreachable | Shell boundary around `MfeOutlet` ([Failure handling](/docs/failure-handling))      |
| Manifest permission preflight denied                             | Shell (`PERMISSION_DENIED`), remote not loaded                                      |
| `beforeLoad` redirect or throw                                   | MFE router, inside the MFE root                                                     |
| Loader error, `notFound()`                                       | Nearest MFE `errorComponent` / `notFoundComponent`                                  |
| Render error in a route component                                | MFE `errorComponent`, then `createMfe({ errorComponent })`, then `MfeErrorBoundary` |

A failing guard never unmounts the MFE or touches the shell. Client-side checks are for routing and UX only; backend services remain authoritative.
