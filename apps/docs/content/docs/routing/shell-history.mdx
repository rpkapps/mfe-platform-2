title: Shell history
description: The shell owns browser history. MFE routers use a private TanStack history adapter backed by the shell navigation contract, with no monkeypatching.
---

## The contract

The host implements `ShellNavigation` (from the core contracts) once, for the whole page:

```ts
interface ShellNavigation {
  getLocation(): ShellLocation // { pathname, search, hash, state?, key? }
  push(href: string, options?: { replace?: boolean; state?: unknown }): void
  replace(href: string, options?: NavigateOptions): void
  back(): void
  forward(): void
  go(delta: number): void
  reload(): void
  subscribe(
    listener: (location: ShellLocation, action: "push" | "replace" | "pop") => void
  ): () => void
  canLeave?(next: string): boolean
}
```

A TanStack Start or TanStack Router shell gets it for free from `@platform/host-react/tanstack`:

```ts title="apps/shell/src/router.tsx"
import { createTanStackShellNavigation } from "@platform/host-react/tanstack"

const navigation = createTanStackShellNavigation(router)
const host = createPlatformHost({ runtimeConfig, registry, navigation })
```

`createTanStackShellNavigation` subscribes to the router's history, forwards `push`/`replace` through `router.navigate` and reports every change to the remotes as `push`, `replace` or `pop`; nothing on `window` is patched. The conformance shell creates it in its root layout and passes it to `createPlatformHost({ navigation })`. A shell without a router uses `createBrowserNavigation` instead: one `popstate` listener and ordinary History API calls.

## The adapter

`createMfeRouter` wraps the bridge's navigation in a private TanStack history (`createShellHistory`) and passes it to `createRouter({ history, basepath: routePrefix })`. The adapter:

- delegates every MFE navigation (`Link`, `navigate`, `redirect`) to `ShellNavigation.push`/`replace`; TanStack already prefixes hrefs with the `basepath`, and `normalizeShellHref` drops the trailing slash TanStack adds to the MFE root (`/well-planner/` → `/well-planner`),
- asks `navigation.canLeave(path)` first when the shell implements it, so a shell can block a navigation,
- receives location changes from the shell (`subscribe`) and feeds them to the router as `PUSH`, `REPLACE`, `BACK`, `FORWARD` or `GO`, so browser back/forward and shell-side navigations update the MFE,
- implements `back`, `forward`, `go` and `reload` by delegation and keeps TanStack's `state` and `key`,
- registers **no** `popstate` listener of its own and never touches `window.history` (the E2E suite asserts that `history.pushState` and `Storage.prototype.setItem` are still native after every fixture has mounted).

### Inactive location

While the shell URL is **outside the MFE's prefix** — another MFE or a shell page is active, or the mount is headless — the router does not see the foreign URL. It sees a synthetic inactive location under its own prefix (`/well-planner/__platform_inactive__`), and its own pushes and replaces are **dropped**. An MFE router can therefore never rewrite a URL it does not own, which is what makes headless mounts (settings owners) and lingering roots safe. When the shell navigates back under the prefix, the real location is delivered again.

## Semantics

| MFE action                                                    | Shell effect                                                                           |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `<Link to="/wells/$wellId" params={{ wellId: "1" }}>`         | `push("/well-planner/wells/1")`                                                        |
| `navigate({ to: "/wells", replace: true })` (TanStack router) | `replace("/well-planner/wells")`                                                       |
| `useNavigation().navigateWithin("/wells/1")`                  | `push("/well-planner/wells/1")`                                                        |
| `useNavigation().navigate("/legacy/reports")`                 | `push("/legacy/reports")` — leaves the MFE; the shell's `$` route swaps the outlet     |
| `useNavigation().back()`                                      | `back()` — may leave the MFE; the shell disposes the root on the next route match      |
| Shell navigates to `/dashboard`                               | MFE router sees the inactive location; the shell disposes the root                     |
| Browser back into the MFE                                     | The shell mounts the MFE; the adapter delivers the current location as the first entry |

## Navigating outside the MFE

`useNavigation()` gives the absolute form for cross-MFE links and the relative form for internal ones:

```tsx
import { useNavigation } from "@platform/mfe-react"

function Links() {
  const nav = useNavigation()
  return (
    <>
      <button onClick={() => nav.navigateWithin("/wells/w01")}>16/2-D-12 H</button>
      <button onClick={() => nav.navigate("/legacy/reports/daily-production")}>
        Daily report
      </button>
    </>
  )
}
```

`nav.location` is the subscribed shell location, `nav.subscribe(listener)` a non-React subscription and `nav.routePrefix` the effective prefix. Inside route files, TanStack's own `Link`, `useNavigate` and `redirect` are the normal way to move within the MFE.

## What is never done

- No patching of `history.pushState`, `history.replaceState`, `window.history` or `popstate`.
- No second `popstate` listener per MFE.
- No global router registry; each MFE router is private to its root.

The platform test suite asserts that `history.pushState === History.prototype.pushState` after every fixture has mounted.
