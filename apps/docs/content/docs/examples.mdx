title: Examples

All apps live under `apps/` in the platform repository and are built with the same packages a consumer uses. `pnpm dev:conformance` starts all of them; `pnpm build:all && pnpm e2e` runs the Playwright suite against them.

## `apps/conformance-shell`

A TanStack Start SSR shell using `@platform/host`. Demonstrates:

- runtime configuration generated by `platform-host-entrypoint` (`config:generate`) and inlined by the server,
- `createTanStackShellNavigation(router)` and the `$`-route helper for `/asset-tracker/$` and `/legacy/reports/$`,
- `MfeOutlet`, `WidgetSlot` (several instances on a dashboard), `CommandPalette`, `SettingsHost`, `HelpSlot`, `ReleaseNotesSlot`, `Breadcrumbs`, `AppFinder`, `NotificationHost`, `PlatformDevtools`,
- user, project and theme switchers that update the context store (slice subscriptions and guard re-runs),
- a shell counter proving that shell state survives remote HMR,
- fixture remotes for failure states: `broken-remote` (invalid manifest), `incompatible-remote` (protocol mismatch), `unavailable-remote` (nothing listens on port 4999), `disabled-remote`, `restricted-remote` (permission preflight).

Ports: 4100 (production build), 4110 (dev).

## `apps/conformance-react19` — `asset-tracker`

React 19 MFE with Tecton. Demonstrates folder routes with guards and loaders (`/assets/$assetId`), loader-derived breadcrumbs, commands with shortcuts and async handlers, a framework-managed settings group with an async select, an MFE-managed settings page, `createPlatformStorage` with a column picker (cross-tab), slice subscriptions with a render counter, `useRuntimeEnv`, telemetry spans, ordinary Tecton dialogs, help entries and release notes, and the `asset-card` widget. Route prefix: `/asset-tracker`. Port 4201.

## `apps/conformance-react18` — `legacy-reports`

React 18 MFE without Tecton, kept on the legacy URL through `routePrefix: "/legacy/reports"`. Demonstrates React 18 coexistence with a React 19 shell (bundled React 18 or a shared `react18` scope with `widget-b`), a modal opened from a React 18 root through the overlay manager, guards, storage, runtime environment and HMR isolation. Port 4202.

## `apps/conformance-widget-a` — `widget-a`

Hidden React 19 widget library (`discoverable: false`, no routes). Widgets: `kpi-tile`, `modal-widget` (opens nested dialogs), `counter-widget` (instance-scoped state, several instances at once), `stacked-modal`. Demonstrates multiple instances, modal ordering across widgets and widget HMR. Port 4203.

## `apps/conformance-widget-b` — `widget-b`

Hidden React 18 widget library. Widgets: `report-summary`, `modal-widget`. Demonstrates React 18 widgets next to React 19 widgets on one dashboard and the `react18` share scope shared with `legacy-reports`. Port 4204.

## Shared fixtures

`internal/conformance` holds the data every app and test agrees on: ports, mfeIds, route prefixes, users (`admin`, `viewer`, `restricted`) with their groups, tenant, projects, jobs, feature flags, assets, reports, runtime environment values and stable `data-testid`s.

## What the E2E suite checks with them

HMR (state preservation, multiple widget instances, React 18/19 isolation, restart diagnostics), folder routing and prefixes, native guards, shell history without History API patching, isolated roots and React coexistence, compatible sharing and incompatible fallback, Tecton and CSS scoping, dialogs without configuration and global modal ordering, command registration/cleanup/conflicts/async, settings (groups, schemas, inference, async options, migrations, invalid values, reset, custom pages), storage (scopes, namespacing, cross-tab), context and slice subscriptions, permissions and guards, runtime environment and Docker configuration, manifest generation and overrides, remote failures, retries and unavailable states, diagnostics, devtools flag and lazy loading, the React Flow graph, release metadata and generated artefact validation.
