All apps live under `apps/` in the platform repository and are built with the same packages a consumer uses. `pnpm dev:conformance` starts all of them in development mode; `pnpm build:all && pnpm e2e` runs the Playwright suite against the built artefacts.

## `apps/conformance-shell`

A TanStack Start SSR shell using `@platform/host` (the reference shell). Demonstrates:

- runtime configuration generated by `platform-host-entrypoint` at container start (`scripts/start.mjs`, `Dockerfile`) and **inlined by the server**: the root route loader calls a server function whose `.server.ts` module reads the document, and the client passes it to `loadRuntimeConfig({ inline })`,
- `createPlatformHost` with a registry, `createTanStackShellNavigation(router)`, `notifications: createSonnerNotificationPort()`, a memory + console telemetry adapter and `policy: { permissionGroups: "all", preflight: true }`,
- the `$` catch-all route: `mfeRouteHelpers({ host }).matchMfeForPath(pathname)` picks the remote by longest prefix and renders `<MfeOutlet key={mfeId} mfeId routePrefix />`,
- a settings page that renders `<SettingsHost />` and mounts the settings owners **headlessly** (`<MfeOutlet mfeId="asset-tracker" routePrefix="/asset-tracker" />` inside a hidden container) so their groups stay registered,
- a dashboard with `WidgetSlot`s from four remotes at once (React 18 and 19 side by side), a KPI prop that updates, a growing list of counters and an unknown widget failing alone,
- `CommandPalette`, `Breadcrumbs`, `HelpSlot`, `ReleaseNotesSlot`, `AppFinder`, `NotificationHost`, `PlatformDevtools` and `ShellOverlayProvider` in the root layout,
- user, project and theme switchers that patch the context store (slice subscriptions and guard re-runs),
- a shell counter proving that shell state survives remote navigation and HMR,
- a **failure lab** route with fixture remotes: `broken-remote` (`MANIFEST_INVALID`), `incompatible-remote` (`PROTOCOL_INCOMPATIBLE`), `unavailable-remote` (nothing listens on port 4999, `MANIFEST_FETCH_FAILED`), `disabled-remote` (`REMOTE_DISABLED`), `restricted-remote` (`PERMISSION_DENIED`).

Ports: 4100 (production build), 4110 (dev).

## `apps/conformance-react19` — `asset-tracker`

React 19 MFE with Tecton, route prefix `/asset-tracker`, port 4201. Demonstrates folder routes with a guard and loader (`/assets/$assetId`: redirect without `assets:read`, guard error for `restricted`), loader-derived breadcrumbs, a root-level command with a shortcut (`mod+shift+d`), commands with shortcuts and an abortable async handler, a framework-managed settings group with an async select and a `visibleWhen` field registered from the root layout, an MFE-managed settings page (`/settings/custom`, session storage), `createPlatformStorage` with a migration and a column picker (cross-tab), slice subscriptions with a render counter, `useRuntimeEnv`, telemetry spans, ordinary Tecton dialogs, static help and release notes, the typed-router `Register` augmentation and the `asset-card` widget. Required env: `API_BASE_URL`.

## `apps/conformance-react18` — `legacy-reports`

React 18 MFE without Tecton, kept on the legacy URL through `routePrefix: "/legacy/reports"`, port 4202. Demonstrates React 18 coexistence with a React 19 shell (its own React 18 in the `react18` share scope, shared with `widget-b`), a guarded report route (`reports:read`, `reports:export`), a versioned store migration (`v2 → v3`), scoped `:root` custom properties, and the widgets `report-summary` (with an HMR marker), `stacked-modal` and `plain-modal` (plain modals opened from a React 18 root through the overlay manager).

## `apps/conformance-widget-a` — `widget-a`

Hidden React 19 widget library with Tecton (`discoverable: false`, no routes), port 4203. Widgets: `kpi-tile` and `modal-widget` (opens nested dialogs). Also contributes a static command (`refresh-kpis`), a help entry and release notes to show that hidden remotes stay full platform citizens.

## `apps/conformance-widget-b` — `widget-b`

Hidden React 18 widget library without Tecton, port 4204. Widget: `counter-widget`, mounted several times with an instance-scoped session store; demonstrates React 18 widgets next to React 19 widgets on one dashboard and the `react18` share scope shared with `legacy-reports`.

## Shared fixtures

`internal/conformance` holds the data every app and test agrees on: ports, mfeIds, users (`admin`, `viewer`, `restricted`) with their groups, tenant, projects, jobs, feature flags, assets, reports, runtime environment values and stable `data-testid`s.

## What the E2E suite checks with them

| Suite                      | Checks                                                                                                                                                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `smoke.spec.ts`            | React 19 and 18 remotes in isolated roots, native History API and storage (no monkeypatching), CSS scoped to the owning remote, runtime env reaching each MFE and secrets never appearing in `/platform-config.json`          |
| `commands.spec.ts`         | palette search and run, shortcut dispatch through the shell, async command with running state and notification, settings fields and help searchable, cleanup on unmount, deterministic shortcut conflicts visible in devtools |
| `history.spec.ts`          | MFE navigation, back, forward and deep links through the shell with the shell never remounted; the legacy prefix; breadcrumbs from route metadata                                                                             |
| `guards.spec.ts`           | guards using permission groups from the context and re-running on context changes; guard errors inside the MFE; slice subscriptions not rerendering on unrelated changes                                                      |
| `widgets.spec.ts`          | widgets from four remotes with independent state; unknown widget failing alone; Tecton dialogs and plain modals stacking in opening order across roots                                                                        |
| `settings-storage.spec.ts` | framework-managed groups rendering, persisting, validating and resetting; invalid stored settings recovering; namespaced cross-tab storage; the MFE-managed page                                                              |
| `failures.spec.ts`         | every failure-lab boundary failing alone with an actionable diagnostic; manifest URL overrides with visible source and clearing                                                                                               |
| `devtools.spec.ts`         | devtools loading only with the flag, as a separate chunk; the dependency graph and overview                                                                                                                                   |
| `hmr.spec.ts`              | React 19 and 18 remotes hot-updating while shell and remote state survive; restart-requiring changes producing a diagnostic; dev manifests marked HMR-capable, production ones not                                            |
