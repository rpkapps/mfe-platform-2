title: "@platform/host"
description: The framework-free shell runtime, its headless command, search and settings APIs, the testing helpers and the Docker entrypoint.
---

`@platform/host` declares **no peer dependencies**: no React, no router, no design system. It is the runtime plus the headless APIs a shell builds its own UI on. React bindings are [`@platform/host-react`](/docs/reference/host-react); the chrome is the shell's own code.

Entry points: `@platform/host` (runtime and headless APIs), `@platform/host/testing` (an in-memory host for testing a shell's chrome), `@platform/host/entrypoint` (runtime configuration generator, also the `platform-host-entrypoint` binary) and `@platform/host/styles.css` (the overlay roots the overlay manager creates).

## `createPlatformHost(options)`

```ts
import { createPlatformHost, loadRuntimeConfig } from "@platform/host"
import { createTanStackShellNavigation } from "@platform/host-react/tanstack"

const host = createPlatformHost({
  runtimeConfig: await loadRuntimeConfig({ inline }), // a parsed RuntimeConfig (required)
  navigation: createTanStackShellNavigation(router), // ShellNavigation (required)
  registry: [{ mfeId: "well-planner", manifestUrl: "https://…/platform-manifest.json", displayName: "Well Planner" }],
  context: { user, permissionGroups, tenant, project, job, locale, timezone, theme, resolvedTheme, featureFlags, environment, release }, // Partial<ShellContextState> or a ShellContextStore
  notifications: myNotificationPort, // NotificationPort, implemented by the shell
  credentials: myCredentialAdapter, // CredentialAdapter (see Authentication)
  telemetry: adapter, // TelemetryAdapter or a Telemetry instance
  policy: { permissionGroups: "all", preflight: true, allowedOrigins?, credentialOrigins?, capabilities?(manifest) },
  devtools: { ...runtimeConfig.devtools, load: () => import("@platform/devtools") },
})
```

| Option                                                                                                                | Description                                                                                                                                                         |
| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `runtimeConfig`                                                                                                       | Required, a validated `RuntimeConfig` ([Runtime configuration](/docs/runtime-configuration))                                                                        |
| `navigation`                                                                                                          | Required `ShellNavigation` ([Shell history](/docs/routing/shell-history))                                                                                           |
| `registry`                                                                                                            | `RegistryEntry[]`: `{ mfeId, manifestUrl?, displayName?, enabled?, preload?, routePrefix?, discoverable? }`                                                         |
| `loader`                                                                                                              | `RemoteLoader`; default: Module Federation (`shared` lists the modules the shell offers: `{ version, lib, singleton?, requiredVersion? }` per name)                 |
| `context`                                                                                                             | Initial shell context or an existing store                                                                                                                          |
| `telemetry`, `storage`, `notifications`, `credentials`                                                                | Adapters; storage defaults to the browser backend, `credentials` is a `CredentialAdapter` ([Authentication](/docs/authentication))                                  |
| `policy`                                                                                                              | `capabilities(manifest)` (default: manifest + implicit), `permissionGroups: "all" \| string[]`, `allowedOrigins`, `credentialOrigins`, `preflight` (default `true`) |
| `devtools`, `overlays`                                                                                                | `{ policy, environments, load }` — `load` is how the shell supplies its tools, e.g. `() => import("@platform/devtools")`; `{ baseZIndex?, document? }`              |
| `environment`                                                                                                         | Defaults to `runtimeConfig.environment`                                                                                                                             |
| `refreshRuntimeConfig`, `defaultManifestUrl`, `fetch`, `origin`, `search`, `sleep`, `diagnosticsLimit`, `autoPreload` | Overrides for `config.refresh()`, the default `/mfes/<mfeId>/platform-manifest.json`, tests and preloading                                                          |

`remotes.mount` returns a `MountedInstance` (`instanceId`, `mfeId`, `bridge`, `handle`, `state`, `dispose(reason?)`); `mountWidget` returns a `WidgetInstance` with `widgetId` and `setProps(props)`. A headless mount keeps the remote's registrations live without breadcrumbs (the container gets `data-platform-headless`).

Other runtime exports: `loadRuntimeConfig({ inline?, url?, fetch?, fallback?, diagnostics?, document?, window?, signal? })`, `readInlineRuntimeConfig`, `diffRuntimeConfig`, `RUNTIME_CONFIG_SCRIPT_ID` (`platform-config`), `RUNTIME_CONFIG_URL`; `resolveManifestUrl`, `assertOriginAllowed`, `fetchManifest`, `createOverrideStore`, `defaultManifestUrl`, `MANIFEST_OVERRIDES_KEY` (`platform:manifest-overrides`), `MANIFEST_QUERY_PREFIX` (`platform.override.`); `createBridge`, `createSettingsValuePort`, `settingsStorageKey`, `approveCapabilities`; `createCommandSearchIndex`, `collectEntries`, `scoreEntry`, `SEARCH_GROUPS`; `runCommand`, `createCommandRunner`, `commandHref`, `isCommandAvailable`; `installShortcutListener`, `isEditableTarget`; `settingsController`, `readSettingsGroupValues`; `shouldLoadDevtools`, `loadDevtools`, `decideDevtools`, `readDevtoolsFlag`, `setDevtoolsFlag`, `DEVTOOLS_FLAG_KEY` (`platform:devtools`), `DEVTOOLS_QUERY` (`platform.devtools`); `stateForError`; and every type from `types.ts` (`PlatformHost`, `PlatformHostOptions`, `RegistryEntry`, `HostPolicy`, `RemoteRecord`, `InstanceRecord`, `MountOptions`, `WidgetMountOptions`, `MountedInstance`, `WidgetInstance`, `RemotesApi`, `CommandRunner`, `HostEvents`…).

## Headless APIs for a shell's own UI

The chrome the platform used to ship — a command palette, a settings page, breadcrumbs, an app
finder — is now the shell's own code, because a shell's design system is not the platform's
business. What the platform keeps is the part that is hard to get right:

| Export                                                                            | What it gives you                                                                                                           |
| --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `createCommandSearchIndex(host)`, `collectEntries`, `scoreEntry`, `SEARCH_GROUPS` | A ranked, grouped search over commands, MFEs, routes, settings, help and release notes — everything a palette lists         |
| `runCommand`, `createCommandRunner`, `commandHref`, `isCommandAvailable`          | Running a command with its state machine, abort support, outcome reporting and telemetry                                    |
| `installShortcutListener(host)`, `isEditableTarget`                               | One keyboard listener that dispatches registered shortcuts and stays out of inputs (`PlatformProvider` installs it for you) |
| `settingsController(...)`, `readSettingsGroupValues`                              | Control inference, validation, persistence, async options and migration for a settings page                                 |
| `outletStateFor` (from `@platform/host-react`)                                    | Which state an error puts an outlet in                                                                                      |

`apps/conformance-shell/src/components` in the platform repository is the reference
implementation of all of it — copy it and restyle it, shadcn-style, rather than depending on it.

## Testing a shell — `@platform/host/testing`

```ts
import {
  createTestHost,
  fakeLoader,
  recordingFetch,
  manifest,
  definition,
} from "@platform/host/testing"

const host = createTestHost({
  fetch: recordingFetch({
    "http://shell.test/mfes/well-planner/platform-manifest.json": manifest(),
  }),
  loader: fakeLoader({ "well-planner": definition() }),
})
```

An in-memory host with memory navigation and storage, a fake loader that answers from a map of
definitions, a manifest builder and a `fetch` that answers from a URL map (with `failures` and
`status` overrides for retry and error paths). Enough to unit-test a shell's chrome with no
browser, no network and no real remote.

## Entrypoint — `@platform/host/entrypoint`

```text
platform-host-entrypoint --out <file> [--base <json file>] [--known <mfeId,...>] [--print]
```

```ts
import { generateRuntimeConfigFile, runEntrypoint } from "@platform/host/entrypoint"
const { config, refused, sources, outPath, json } = generateRuntimeConfigFile({
  out,
  base,
  known,
  env,
  cwd,
})
```

Reads only `PLATFORM_*` variables, refuses sensitive-looking names, validates the document and writes it with `$schema`. See [Runtime configuration](/docs/runtime-configuration).

## Styles

`@platform/host/styles.css` is small on purpose: it styles the overlay roots and layers the
host's overlay manager creates, and nothing else. Outlet layout ships with
[`@platform/host-react/styles.css`](/docs/reference/host-react); the developer tools bring
`@platform/devtools/styles.css`; the chrome's own styles belong to the shell.

## Core helpers re-exported by the host

Shells compose the host from adapters and backends that live in the platform core; `@platform/host` re-exports them so a shell outside this repository never depends on an internal package: `createConsoleTelemetryAdapter`, `createMemoryTelemetryAdapter`, `composeTelemetryAdapters`, `createTelemetry`, `createBrowserNavigation`, `createMemoryNavigation`, `createBrowserStorageBackend`, `createMemoryStorageBackend`, `createShellContextStore`, `createPermissionHelpers`, `PlatformError`, `ERROR_CODES`, `validateManifest`, `parseRuntimeConfig`, `generateRuntimeConfig`, and the types `Telemetry`, `TelemetryAdapter`, `ShellNavigation`, `StorageBackend`, `ShellContextState`, `MfeManifest`, `RuntimeConfig`, `HostBridge`, `RemoteDefinition`, `RemoteLoader`. A shell on TanStack Router uses `createTanStackShellNavigation` from [`@platform/host-react/tanstack`](/docs/reference/host-react#tanstack-bridge).
