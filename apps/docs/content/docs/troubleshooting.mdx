## Reading a diagnostic

```text
[platform:MANIFEST_ORIGIN_DENIED] Manifest origin https://cdn.other.com is not allowed.
  owner: asset-tracker
  source: https://cdn.other.com/asset-tracker/platform-manifest.json
  override: PLATFORM_ALLOWED_ORIGINS or mfes.asset-tracker.allowedOrigins
  hint: Add the origin to `allowedOrigins` in the host configuration or use a same-origin manifest URL.
  docs: https://platform.docs.local/docs/manifest-overrides#origin-validation
```

1. **code**: stable identifier, listed below.
2. **owner**: which MFE, widget or instance the failure belongs to.
3. **source**: the artefact that caused it (URL, package, key).
4. **override**: the switch an operator or developer can use right now.
5. **hint** and **docs**: what to do and where to read.

The same fields appear in the boundary UI, the developer tools _Events_ panel, `PlatformError.toJSON()` and telemetry.

## Common situations

**The remote loads in the harness but not in the shell.** Check the devtools _Overview_ tab: is the effective URL the one you expect, and what is its source? A stale `localStorage["platform:manifest-overrides"]` entry from a previous session is the usual cause.

**My change does not appear.** The loaded remote may be a production artefact (`vite preview`) rather than the dev server; only dev manifests carry a `dev` block and the harness `HMR` badge. Or a restart is required (`DEV_RESTART_REQUIRED`).

**A dialog is unstyled or clipped.** The overlay root is missing the owner attribute (`OVERLAY_FAILED`) or the remote was built with `css.scope: false`. Inspect `[data-platform-overlay-root]` elements on `body`.

**Two React copies.** `shared.resolved` in the devtools shows `bundled` for `react` with the reason (wrong scope, unsatisfied range). This is expected for a React 18 remote in a React 19 shell without another React 18 provider.

**A command's shortcut does nothing.** Look for `shortcut.conflict` in the events: the first registration keeps the shortcut.

**Storage resets on every load.** `storage.invalid` in the events shows the schema issue; add a `migrate` or bump `version`.

## Reporting

Copy the diagnostic from the devtools _Events_ panel (it is `PlatformError.toJSON()` plus context) and attach the manifest URL and the shared-dependency report. Every platform test fixture can be reproduced with `pnpm dev:conformance`.
