---
title: Create an MFE
description: Scaffold a complete, runnable micro-frontend with one command, then load it into a shell with a manifest override.
---

<Steps>

<Step>Scaffold the project</Step>

```bash
pnpm dlx @platform/cli create my-mfe
```

The command asks for nothing it can infer. It creates a TanStack Router project with the platform integration, Tecton UI, Tailwind CSS with selector isolation, unit and end-to-end tests, the lint configuration and the AI guidance files, then runs `git init` and `pnpm install`. Pass `--react 18` for a React 18 remote, `--no-tecton` for plain markup, `--no-install` / `--no-git` to skip those steps, `--mfe-id` / `--display-name` to override the inferred identity, or `--link-platform <monorepo>` to install the platform packages from a checkout. All flags: [`platform create`](/docs/reference/platform-cli#create).

<Step>Start</Step>

```bash
cd my-mfe
pnpm dev
```

`pnpm dev` runs `platform dev`: a Vite dev server for the remote, serving its development manifest at `http://localhost:5173/platform-manifest.json`. Load it into a shell with a manifest override:

```text
https://shell.example.com/my-mfe?platform.override.my-mfe=http://localhost:5173/platform-manifest.json
```

Your MFE hot-reloads inside that shell, with the shell's real context and — against a deployed development shell — its real session. See [Local development](/docs/local-development).

<Step>Build</Step>

```bash
pnpm build
```

`platform build` runs the Vite production build and validates the result. `dist/` contains the remote entry (`remoteEntry.js`), `mf-manifest.json`, code-split route chunks, scoped CSS and `platform-manifest.json`. Deploy `dist/` to any static origin; the shell loads it from the manifest URL.

</Steps>

## The bootstrap file

`src/mfe.tsx` is the only platform-specific file you need to know about. It default-exports the remote definition; the generated entry (`.platform/entry.tsx`) wraps it with `withTecton` and exposes it to the host.

```tsx title="src/mfe.tsx"
import { createMfe, createWidget } from "@platform/mfe-react"
import { z } from "zod"

import "./styles.css"
import { routeTree } from "./routeTree.gen"
import { WellSummary } from "./widgets/well-summary"

export default createMfe({
  routeTree,
  widgets: {
    "well-summary": createWidget({
      title: "Well summary",
      component: WellSummary,
      propsSchema: z.object({ wellId: z.string(), compact: z.boolean().optional() }),
    }),
  },
  registrations: {
    help: [{ id: "getting-started", title: "My MFE: getting started", route: "/" }],
    releaseNotes: [
      { id: "v0-1-0", version: "0.1.0", title: "My MFE 0.1.0", summary: "Initial release." },
    ],
  },
})
```

`mfeId` is inferred from the package name (`@acme/my-mfe` → `my-mfe`) and persisted in `.platform/identity.json`, so renaming the package later does not change storage keys or command ids. See [Manifests](/docs/manifests#mfe-id).

## Typed routes

`src/platform.d.ts` registers the MFE router with TanStack, so `Route.useLoaderData()`, `Route.useSearch()`, `Link to` and `params` are typed everywhere in the MFE, and it types the runtime environment and feature flags:

```ts title="src/platform.d.ts"
import "@platform/mfe-react"
import type { MfeRouter } from "@platform/mfe-react"

import type { routeTree } from "./routeTree.gen"

declare module "@platform/mfe-react" {
  interface Register {
    env: { API_BASE_URL: string }
    featureFlags: { "wells.bulk-edit": boolean }
  }
}

declare module "@tanstack/react-router" {
  interface Register {
    router: MfeRouter<typeof routeTree>
  }
}
```

Keep `env` in step with `mfe.config.ts → env`.

## Scripts

| Script           | Runs                                                                                |
| ---------------- | ----------------------------------------------------------------------------------- |
| `pnpm dev`       | `platform dev` — Vite dev server + the development manifest a shell can load        |
| `pnpm build`     | `platform build` — production remote, manifest validation and summary               |
| `pnpm preview`   | `vite preview` — serve `dist/` as a production artefact                             |
| `pnpm manifest`  | `platform manifest` — print the manifest inferred from the sources                  |
| `pnpm validate`  | `platform validate` — structure, identity, configuration, generated files, manifest |
| `pnpm lint`      | `platform lint` — the shareable ESLint config                                       |
| `pnpm test`      | `platform test` — Vitest (`src/**/*.test.{ts,tsx}`)                                 |
| `pnpm typecheck` | `tsc --noEmit`                                                                      |
