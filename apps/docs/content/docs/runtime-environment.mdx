---
title: Runtime environment
description: Typed, allow-listed runtime values per MFE, provided by the shell at container start rather than baked in at build time.
---

## Declare the keys

```ts title="mfe.config.ts"
import { defineMfeConfig } from "@platform/vite/config"

export default defineMfeConfig({
  env: {
    API_BASE_URL: { required: true, description: "Base URL of the wells API" },
    PAGE_SIZE: { default: 25 },
    FEATURE_MAP: { default: false, description: "Show the map view" },
  },
})
```

The declaration is an **allow-list**: only these keys reach the MFE, with `default` applied when the runtime configuration omits one. A `required` key that is missing fails the mount with a clear diagnostic instead of an undefined value deep in the code. The declaration is written to the manifest (`env.keys`) so operators can see what an MFE expects.

## Type them

```ts title="src/platform.d.ts"
import "@platform/mfe-react"

declare module "@platform/mfe-react" {
  interface Register {
    env: { API_BASE_URL: string; PAGE_SIZE: number; FEATURE_MAP: boolean }
    featureFlags: { "wells.bulk-edit": boolean }
  }
}
```

The `Register` interface follows TanStack's pattern: augment it once and `useRuntimeEnv()`, `usePlatform((p) => p.runtime.env)` and `context.platform.runtime.env` are typed everywhere.

## Read them

```tsx
import { useRuntimeEnv } from "@platform/mfe-react"

function AssetList() {
  const env = useRuntimeEnv()
  const { data } = useQuery(assetsQuery(env.API_BASE_URL, env.PAGE_SIZE))
  return …
}
```

In loaders: `context.platform.runtime.env.API_BASE_URL`. In command handlers and option providers: `platform.runtime.env`.

`runtime.shared` holds the values every MFE receives (`PLATFORM_SHARED_*`), and `runtime.environment` names the deployment (`production`, `staging`, `local`).

## Where values come from

| Source            | Example                                                              |
| ----------------- | -------------------------------------------------------------------- |
| Docker entrypoint | `PLATFORM_MFE_WELL_PLANNER_ENV_API_BASE_URL=https://api.example.com` |
| Static document   | `mfes.well-planner.env.API_BASE_URL` in `/platform-config.json`      |
| Local development | `mfe.config.ts` defaults, or the shell's own `PLATFORM_*` variables  |
| Tests             | `createTestBridge({ env: { API_BASE_URL: "http://test" } })`         |

See [Runtime configuration](/docs/runtime-configuration).

## Build-time variables

`import.meta.env.VITE_*` still works for values that are genuinely build constants, but it cannot change per container. The [`@platform/no-unsafe-runtime-env-access`](/docs/linting#no-unsafe-runtime-env-access) lint rule reports `import.meta.env`, `process.env`, `window.__PLATFORM_CONFIG__` and `/platform-config.json` reads in MFE code, pointing at `useRuntimeEnv`.

## Never secrets

Runtime environment values are public by contract: they are delivered to the browser. The entrypoint refuses variable names that look sensitive (`SECRET`, `PASSWORD`, `TOKEN`, `PRIVATE`, `CREDENTIAL`, `API_KEY`, `_KEY`), and an MFE never receives another MFE's values. See [Unsupported cases](/docs/unsupported-cases).
