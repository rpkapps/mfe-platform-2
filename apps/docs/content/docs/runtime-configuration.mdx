title: Runtime configuration
description: A shell-owned, client-safe configuration document generated when the container starts, validated before the platform boots, organised by mfeId.
---

## Why

Docker images are built once and started many times with different manifest URLs, enabled MFEs and API endpoints. Build-time Vite variables cannot express that. The runtime configuration document is generated at container start by a cross-platform Node entrypoint and served to the browser.

## Docker entrypoint

`@platform/host` ships `platform-host-entrypoint`:

```text
platform-host-entrypoint --out <file> [--base <json file>] [--known <mfeId,...>] [--print]
```

The conformance shell is the reference: its Dockerfile builds the assets once and starts `scripts/start.mjs`, which runs the entrypoint and then serves the built shell (`vite preview` there; a deployment hosts `dist/server/server.js` with its own Node adapter):

```js title="apps/conformance-shell/scripts/start.mjs"
const out = join(app, "dist", "client", "platform-config.json")
const generated = spawnSync(process.execPath, [entrypoint, "--out", out], { stdio: "inherit" })
if (generated.status !== 0) process.exit(generated.status ?? 1)
spawn(
  process.execPath,
  [vite, "preview", "--port", port, "--strictPort", "--host", "0.0.0.0"],
  {
    env: { ...process.env, PLATFORM_CONFIG_PATH: out },
  }
)
```

```json title="package.json (shell)"
{
  "scripts": {
    "config:generate": "platform-host-entrypoint --out ./dist/client/platform-config.json",
    "start": "node ./scripts/start.mjs"
  }
}
```

The entrypoint reads only `PLATFORM_*` variables, merges them over an optional base document (`--base`), validates the result against the schema, writes it with `$schema` (`--out`) and/or prints it (`--print`). It exits non-zero on validation errors (`RUNTIME_CONFIG_INVALID`) and logs which variable produced which key and which variables were refused. `generateRuntimeConfigFile()` from `@platform/host/entrypoint` does the same programmatically.

## `PLATFORM_*` variables

| Variable                                                                           | Key                                            |
| ---------------------------------------------------------------------------------- | ---------------------------------------------- |
| `PLATFORM_ENVIRONMENT`                                                             | `environment`                                  |
| `PLATFORM_RELEASE_VERSION`, `PLATFORM_RELEASE_BUILD_ID`, `PLATFORM_RELEASE_COMMIT` | `release.*`                                    |
| `PLATFORM_SHARED_<KEY>`                                                            | `shared.<KEY>` (every MFE receives it)         |
| `PLATFORM_ALLOWED_ORIGINS`                                                         | `allowedOrigins` (comma separated)             |
| `PLATFORM_DEVTOOLS_POLICY`                                                         | `devtools.policy` (`flag`, `always`, `never`)  |
| `PLATFORM_MFE_<ID>_ENABLED`                                                        | `mfes.<id>.enabled`                            |
| `PLATFORM_MFE_<ID>_MANIFEST_URL`                                                   | `mfes.<id>.manifestUrl`                        |
| `PLATFORM_MFE_<ID>_PRELOAD`                                                        | `mfes.<id>.preload` (`none`, `entry`, `eager`) |
| `PLATFORM_MFE_<ID>_ALLOWED_ORIGINS`                                                | `mfes.<id>.allowedOrigins`                     |
| `PLATFORM_MFE_<ID>_ENV_<KEY>`                                                      | `mfes.<id>.env.<KEY>`                          |

`<ID>` is the `mfeId` upper-cased with `-` → `_` (`asset-tracker` → `ASSET_TRACKER`). Values `true`/`false` become booleans and numeric strings become numbers. Pass `--known asset-tracker,legacy-reports` (or a base document) so ids containing digits or ambiguous separators map unambiguously.

```bash
PLATFORM_ENVIRONMENT=staging \
PLATFORM_MFE_ASSET_TRACKER_MANIFEST_URL=https://remotes.example.com/asset-tracker/platform-manifest.json \
PLATFORM_MFE_ASSET_TRACKER_ENV_API_BASE_URL=https://api.staging.example.com \
PLATFORM_MFE_LEGACY_REPORTS_ENABLED=false \
platform-host-entrypoint --out ./public/platform-config.json
```

## The document

```json title="/platform-config.json"
{
  "schemaVersion": 1,
  "generatedAt": "2026-03-02T08:00:00.000Z",
  "source": "entrypoint",
  "environment": "staging",
  "release": { "version": "3.4.0", "commit": "9f2c1a" },
  "shared": { "SUPPORT_URL": "https://support.example.com" },
  "mfes": {
    "asset-tracker": {
      "manifestUrl": "https://remotes.example.com/asset-tracker/platform-manifest.json",
      "env": { "API_BASE_URL": "https://api.staging.example.com" }
    },
    "legacy-reports": { "enabled": false, "env": {} }
  },
  "devtools": { "policy": "flag", "environments": ["development", "local", "test", "staging"] },
  "cache": { "manifestMaxAgeSeconds": 60, "bustOnRetry": true },
  "retry": { "attempts": 2, "backoffMs": 500 },
  "allowedOrigins": ["https://remotes.example.com"]
}
```

Schema: [`/schemas/runtime-config.json`](/schemas/runtime-config.json), reference: [Runtime config schema](/docs/reference/runtime-config-schema).

## Loading

`createPlatformHost({ runtimeConfig })` takes a validated document. `loadRuntimeConfig()` from `@platform/host` obtains it, in this order: `inline` option → `<script id="platform-config" type="application/json">` or `window.__PLATFORM_CONFIG__` → same-origin fetch of `/platform-config.json` (`cache: "no-store"`, a 404 is tolerated) → `fallback` → schema defaults.

- **SSR inline** (the conformance shell): the root route loader calls a TanStack Start server function that reads the generated file (`PLATFORM_CONFIG_PATH`, then `dist/client/platform-config.json`, then `public/platform-config.json`; in development it derives the document from the same `PLATFORM_*` variables on every request). The file-system code lives in a `.server.ts` module that never reaches the client bundle; the browser receives the document in the initial HTML and passes it as `loadRuntimeConfig({ inline })`.
- **Same-origin JSON**: serve `/platform-config.json` and call `loadRuntimeConfig()` without `inline`.

```ts title="src/lib/runtime-config.ts"
export const getRuntimeConfig = createServerFn({ method: "GET" }).handler(async () => {
  const { readRuntimeConfig } = await import("./runtime-config.server")
  return readRuntimeConfig()
})
```

A fetch failure raises `RUNTIME_CONFIG_FETCH_FAILED`: serve `/platform-config.json` from the same origin or inline it. The effective origin is recorded in `config.source` and in the `runtime-config.loaded` diagnostic.

## Validation

The document is validated before the platform starts, in the entrypoint and again in the host. Invalid documents raise `RUNTIME_CONFIG_INVALID` listing every issue (`mfes.Asset-Tracker: mfeId must be kebab-case`). The platform never starts with a partially valid configuration.

## Per-MFE enablement

`mfes.<mfeId>.enabled: false` (or `enabled: false` on the registry entry) disables a remote everywhere: `MfeOutlet` shows the _disabled_ state, widgets from it do not mount, the App Finder hides it and it is never preloaded. Loading it raises `REMOTE_DISABLED`; re-enable with `PLATFORM_MFE_<ID>_ENABLED=true`. Remotes absent from `mfes` are enabled by default when the registry knows them. The conformance failure lab shows the state for `disabled-remote`.

## Precedence

For every manifest URL and every setting that both sides can express:

```text
explicit local override      (?platform.override.<mfeId>=…, localStorage["platform:manifest-overrides"])
runtime configuration        (/platform-config.json, inline document)
host/platform registry       (createPlatformHost({ registry }))
generated manifest default   (remote.baseUrl, loadPolicy, preload, allowedOrigins)
```

## Refresh

`host.config.refresh()` re-fetches `/platform-config.json` (or calls the `refreshRuntimeConfig` option), validates it, emits `config.changed` with the list of changed keys (`diffRuntimeConfig`) and applies changes that are safe at runtime: enablement, environment values (subscribers update through the context store), preload hints and allowed origins. `host.config.get()` and `host.config.subscribe()` expose the current document. Manifest URL changes apply to the next load of a remote; already mounted instances keep running until they are unmounted.

## Cache

The document is fetched with `Cache-Control: no-cache` semantics; the entrypoint writes it with a `generatedAt` stamp so proxies can be checked. `cache.manifestMaxAgeSeconds` and `cache.bustOnRetry` govern manifest fetches, not the configuration itself.

## Sensitive values refused

Variables whose names match `SECRET`, `PASSWORD`, `PASSWD`, `TOKEN`, `PRIVATE`, `CREDENTIAL`, `API_KEY`, `APIKEY` or end in `_KEY` are never written, even under `PLATFORM_*`. The entrypoint lists the refused names on stderr and continues. The developer tools show the configuration with such keys masked defensively; MFE code receives only its own `env` block and `shared`.

## Local development

The harness builds its own document (`environment: "local"`, devtools always on, no manifest cache) and its _Remotes_ page has an editor for each remote's allow-listed `env`; `mfe.config.ts` `default` values apply when a key is omitted. The conformance shell in development derives the document from `PLATFORM_*` variables on every request (`scripts/dev-conformance.mjs` sets them). See [Local development](/docs/local-development).
