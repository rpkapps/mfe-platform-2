title: Developer tools
description: A private, lazily loaded panel in the host that shows the diagnostic snapshot, the live event stream and the shared-dependency graph.
---

## Enabling

Developer tools load only in the browser when all three hold:

1. the flag is set: `localStorage.setItem("platform:devtools", "1")` or `?platform.devtools=1` on the page URL (the harness has a toggle; `setDevtoolsFlag(true)` from `@platform/host` does the same),
2. the host policy permits it: `devtools.policy` is `flag` (default) or `always` — `never` disables them entirely,
3. the environment is supported: `devtools.environments` (default `development`, `local`, `test`, `staging`) contains the host `environment`.

The policy comes from the runtime configuration (`devtools`, set with `PLATFORM_DEVTOOLS_POLICY`) or from `createPlatformHost({ devtools })`. Otherwise `PlatformDevtools` renders nothing and a `devtools: denied` diagnostic names the reason (`policy-never`, `environment`, `flag-missing`); `DEVTOOLS_UNAVAILABLE` points here.

```tsx title="apps/shell/src/routes/__root.tsx"
import { PlatformDevtools } from "@platform/host/react"

;<PlatformDevtools /> // props: defaultOpen?, force?, className?
```

`force` bypasses the flag and policy (harness, tests). The E2E suite loads the conformance dashboard, asserts that no devtools or React Flow chunk was requested, sets the flag, reloads and opens the panel.

## Lazy loading

The panel, React Flow and their styles live in `@platform-internal/devtools`, bundled into `@platform/host` as a separate chunk that `loadDevtools(host)` `import()`s on first open (`devtools: loaded`). The MFE SDK bundle contains none of it. When the chunk fails to load the host records `devtools: failed` and keeps running.

## Panels

| Tab          | Shows                                                                                                                                                                              |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview     | every known remote with its state, manifest URL and source (`query`, `override`, `runtime-config`, `registry`, `default`), version, protocol, React and router versions, instances |
| Dependencies | shared versus bundled packages per MFE, version-group resolution, and the React Flow graph of providers and requesters (`react18`, `react19`, `default`)                           |
| Routes       | route matches per instance (`route.matched`, `route.guard`, `route.error`)                                                                                                         |
| Commands     | registered commands with their qualified ids, shortcuts, states and shortcut conflicts                                                                                             |
| Settings     | registered groups and fields, invalid stored values                                                                                                                                |
| Breadcrumbs  | shell entries and the active trail                                                                                                                                                 |
| Help         | help entries and release notes per MFE                                                                                                                                             |
| Session      | user, permission groups, tenant, project, job, theme, feature flags                                                                                                                |
| Runtime      | the runtime configuration with sensitive-looking keys masked (`redactRuntimeConfig`), per-MFE env                                                                                  |
| Telemetry    | the recorded telemetry events (`host.telemetryEvents()`)                                                                                                                           |
| Diagnostics  | every diagnostic event with level filters                                                                                                                                          |
| Overlays     | open overlay roots and layers with owner and z-index                                                                                                                               |

## Read-only and redacted

The panel works on `host.snapshot()`, a frozen copy of the host state; it never mutates registries. `PlatformError`s are shown serialised (`toJSON()`), including `owner`, `source`, `override`, `hint` and `docsUrl`. Manifest overrides can be changed from the harness _Remotes_ page or with `host.remotes.setLocalOverride(mfeId, url)`.

## In tests

`decideDevtools(host, window)` returns `{ allowed, reason }` without side effects; `shouldLoadDevtools(host)` also emits the diagnostic. The E2E suite asserts that the devtools chunk is not requested until the flag is set and the toggle is pressed, that the dependency graph shows both share scopes, and that the overview lists `asset-tracker` and `widget-b` with their React versions.
