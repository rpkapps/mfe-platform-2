---
title: Widgets
description: Widgets are React components that the shell or other surfaces mount into slots, each in its own React root, with typed props.
---

## Defining a widget

A widget is an ordinary component. `createWidget` attaches its metadata and props schema; the definition lives in `src/mfe.tsx` under a kebab-case key that becomes the widget id:

```tsx title="src/widgets/well-summary.tsx"
import { useMfeInstance, useNavigation, useRegisterCommand } from "@platform/mfe-react"

export function WellSummary({ wellId, compact }: { wellId: string; compact?: boolean }) {
  const navigation = useNavigation()
  const { instanceId, routePrefix } = useMfeInstance()
  useRegisterCommand({
    id: "open-well",
    label: `Open ${wellId}`,
    handler: () => navigation.navigate(`${routePrefix ?? ""}/wells/${wellId}`),
  })
  return (
    <Card data-instance={instanceId} className={compact ? "py-2" : undefined}>
      …
    </Card>
  )
}
```

```tsx title="src/mfe.tsx"
import { createMfe, createWidget } from "@platform/mfe-react"
import { z } from "zod"

export default createMfe({
  routeTree, // omit it for a widget-only library
  widgets: {
    "well-summary": createWidget({
      title: "Well summary",
      description: "Summary card for one well with a details dialog.",
      component: WellSummary,
      propsSchema: z.object({ wellId: z.string(), compact: z.boolean().optional() }),
    }),
  },
})
```

`createWidget({ id?, component, propsSchema?, title?, description? })`: `id` defaults to the record key (it is required in the array form `widgets: [createWidget({ id, … })]`).

## Registration

The definition lists every widget (`widgets[]`: `id`, `title`, `description`); the manifest lists the ones written as inline `createWidget` calls, so the shell knows about them before loading. A slot that requests an unknown id fails with `WIDGET_UNKNOWN`: export the widget from `createMfe({ widgets })` and rebuild (the conformance dashboard mounts `does-not-exist` on purpose to show the isolated error state).

## Mounting from the shell

```tsx title="apps/shell/src/routes/dashboard.tsx"
import { WidgetSlot } from "@platform/host-react"

<WidgetSlot mfeId="well-planner" widgetId="well-summary" slot="dashboard-well-summary" props={{ wellId: "w01" }} />
<WidgetSlot mfeId="subsurface-widgets" widgetId="production-kpi" slot="kpi-1" props={{ label: "Production", value: kpi, unit: "bbl/d" }} />
<WidgetSlot mfeId="field-widgets" widgetId="rig-status" slot="counter-0" props={{ label: "Counter 1", step: 1 }} />
```

`WidgetSlot` props: `mfeId`, `widgetId`, `props?`, `slot?` (a stable name for the instance, reported in diagnostics), `fallback?`, `errorFallback?(error, retry)`, `className?`. Each slot produces a separate **instance** with its own React root, `instanceId`, overlay root and command namespace. Props are plain data, validated against `propsSchema` on mount and on every update; invalid props render the slot's error state (`data-platform-widget-state="error"`) without touching other instances. Programmatically: `host.remotes.mountWidget(mfeId, widgetId, { container, props, slot? })` returns a `WidgetInstance` with `setProps(props)` and `dispose()`.

## Props

- Props are validated synchronously with the Standard Schema you pass (Zod, Valibot, ArkType…). Without a schema they are passed through untyped.
- Updates arrive through `WidgetHandle.setProps`; the component re-renders in place (the conformance dashboard bumps a KPI prop).
- Props never contain React elements, callbacks that return elements, or class instances: they cross a root boundary as data (`@platform/no-cross-root-component-passing`).

## Instances

`useMfeInstance()` returns `{ mfeId, instanceId, widgetId, routePrefix?, displayName?, host }`. Anything the platform manages is namespaced per instance where it matters:

| Surface   | Namespace                                                                         |
| --------- | --------------------------------------------------------------------------------- |
| Commands  | `<mfeId>:<id>@<instanceId>` (widget commands are always instance-scoped)          |
| Storage   | `platform:<mfeId>:<instanceId>:<scope>:<key>` when `instanceScoped: true`         |
| Overlays  | owner-tagged root per instance (`data-platform-instance`, `data-platform-widget`) |
| Telemetry | `instanceId` and `widgetId` attributes on every event                             |
| Settings  | shared per MFE; a second instance registering the same group is a no-op           |

The `rig-status` fixture (React 18, `field-widgets`) mounts several times on the conformance dashboard with an instance-scoped session store; every instance keeps its own count.

## Overlays from widgets

Widgets open ordinary Tecton dialogs, popovers and menus. The overlay manager creates a body-level, owner-tagged root per instance, so a dialog from a small card is never clipped and still receives the MFE's scoped styles. Dialogs from different widgets — even React 18 and React 19 ones — stack in opening order; see [Modal ordering](/docs/overlays/modal-ordering).

## Failure isolation

A widget that throws during mount or render fails alone: the slot shows the error state with a retry button, `WIDGET_MOUNT_FAILED` is reported with the owner (`mfeId / widget <id> / instance <id>`), and every other widget, the route MFE and the shell keep running. Disposing a slot unmounts the root, clears its registrations and removes its overlay root.

## Widget-only libraries

A remote without routes is a widget library:

```tsx title="src/mfe.tsx"
export default createMfe({
  widgets: { "production-kpi": createWidget({ … }), "fda-status": createWidget({ … }) },
  registrations: { commands: [{ id: "refresh-kpis", label: "Refresh KPIs", group: "Widgets" }], help: [{ id: "production-kpis", title: "KPI tiles" }] },
})
```

Its manifest has `kind: "widget-library"`, `hasRoutes: false` and no `routePrefix`; `mount()` fails with `MOUNT_FAILED` because there is no route tree. Set `discoverable: false` in `mfe.config.ts` so the App Finder skips it ([Hidden MFEs](/docs/hidden-mfes)); the `$` route helper never matches it. Under Vite, a project without `src/routes` gets no router plugin and no route tree.

## Testing a widget

```ts
import { createTestBridge } from "@platform/mfe-react/testing"
import definition from "../mfe"

const bridge = createTestBridge({
  mfeId: "well-planner",
  widgetId: "well-summary",
  routePrefix: null,
})
const container = document.body.appendChild(document.createElement("div"))
const handle = definition.mountWidget({
  container,
  bridge,
  widgetId: "well-summary",
  props: { wellId: "w01" },
})
expect(container.querySelector('[data-platform-widget="well-summary"]')).not.toBeNull()
handle.setProps({ wellId: "w03" })
handle.dispose()
```
